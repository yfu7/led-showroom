# Veloxity Showroom — working notes

- **This directory is the project.** `led-showroom-v2/` is the app and `master` is the v2 line; run every command from here, not from the repo root. v1 (`../index.html`, `../server.js`) is deprecated, frozen, and has no deployment — its Vercel project is deleted and its `/proxy` route answers 410. Do not add to v1 or revive its proxy; see `../README.md`.

- Run: `npm run dev` (Vite, 5173) and `npm run server` (proxy + splat API, 3001). `npm run typecheck`, `npm test` (vitest, node env).
- `src/engine` never imports React. UI reads from the Zustand store (`src/app/store.ts`) and writes through `Engine` (`engine.update / run / patchSettings / patchEnvironment`) so everything is undoable. Continuous edits pass a `mergeKey`; call `engine.history.commit()` when a gesture ends.
- Units: 1 world unit = 1 inch, Y up, floor at y = 0, document angles in degrees. LED walls, equipment and stages have their origin at the bottom centre; `applyTransform` handles degree/radian conversion.
- Renderers: one `EntityRenderer` per entity type in `src/engine/entities` (registry in `entities/index.ts`); the `SceneManager` diffs the document structurally. Renderers set `needsCss3d` / `needsPixelGrid` so the layered `Renderer` can skip passes.
- Tools live in `src/engine/tools` (registry in `tools/index.ts`); a tool claims the left button by returning `true` from `onPointerDown`, otherwise the camera rig orbits.
- Right-click: `ToolManager` eats the browser menu on the viewport (that is all its `contextmenu` handler does) and raises the menu from the right-button *pointerup* — `contextmenu` fires on mouse*down* on macOS/Linux, so the click-vs-drag test cannot live there. It offers the point to the active tool (`Tool.onContextMenu`, return `true` to consume) and otherwise to `ToolManager.onContextMenu(fn)` subscribers — `ViewportOverlay` is the one subscriber. A right-*drag* is still a camera pan and raises no menu. Pick through `engine.pickAt(ndc)`, never a bare `pickEntity`: three's raycaster ignores `visible`, so hidden entities would keep swallowing clicks.
- One menu surface: `components/MenuPanel.tsx` (items, keyboard, submenus). `Menu` anchors it to a trigger, `useContextMenu()` puts it at a point. Both announce themselves on `MENU_OPEN_EVENT` and dismiss on it, so only one menu tree is ever up. The item lists all live in `src/app/menus/entityMenu.tsx` so the viewport, Objects panel and Content panel stay in step.
- Catalog cards: a photographed product shows its cutout from `public/products/` (`EquipmentDef.image`), everything else a lucide line icon. Cards drag two ways — onto the viewport to place the item, onto a sibling card to reorder the group. The order is per-group ids in localStorage (`panels/catalogOrder.ts`); it is resolved against the *unfiltered* group so reordering during a search cannot drop the hidden items, and unlisted ids sort after listed ones so a new product never disappears. Right-click a group header to reset it.
- Manufacturer CAD: the SolidWorks STEP files in `../cad/step` are the source of truth for the iPoster. `npm run cad` (`scripts/step-to-glb.cjs`, occt-import-js) converts them to `public/models/*.glb` in inches, each re-framed to the origin the renderer wants. `content/cadModels.ts` is the shared load/anchor/swap seam; `ledwall/geometry.ts` keeps its parametric extrusion as the synchronous placeholder and adopts the CAD mesh when it arrives, and only for a spec the CAD actually matches. The panel itself stays parametric — it needs UVs, mitring and content mapping that a CAD solid has no way to carry. Panel constants (25.2 x 18.9 x 1.77 in) are inch-authored CAD, cross-checked against the 6x5 wall assembly; do not re-round them to millimetres.
- LED maths (`src/engine/ledwall/*`), calibration, video and v1 import are pure ports of the legacy `../index.html` with tests; keep the cited v1 line references in JSDoc when changing behaviour.
- Design tokens are in `src/app/styles/tokens.css`: 70 % veloxity.us in blue-and-black — Manrope, the brand cyan #28ace3 as the only accent, pill controls with 2px borders that invert on hover, rounded trays, hairlines not shadows. The 30 % luxury is modern, not classical: no serif anywhere, just extra-light Manrope at display sizes with very tight tracking, plus tracked uppercase micro-labels. "Night" is the default theme, "Studio" the light alternate. Only tokens, never hex; sentence case copy; lucide icons at 1.5 stroke.
- Scratch design/inventory docs from the rebuild session: the v1 feature inventory's "must not lose" checklist is the acceptance list for parity.
